Seu laboratório offline

PHP, Java, Python, MariaDB, Git, Composer, pip e VS Code em uma pasta. Cada cópia pertence a um aluno. Ferramentas próprias para Windows 11 x64 e Linux Mint x64; a validação na versão exata do laboratório deve ser feita pelo professor.

Primeiro uso: copie a pasta inteira para um local onde você possa gravar. No Windows, prefira um caminho curto, como C:\Users\seu-usuario\aulas, para evitar o limite de caminhos de algumas ferramentas. Execute dali. O pendrive serve para transportar. Não compartilhe uma mesma cópia entre alunos simultaneamente.

1. Abrir

Windows: abra iniciar-windows.cmd. Não precisa abrir como administrador.

Linux Mint: abra um terminal na pasta do kit e execute:

sh iniciar-linux.sh

Escolha 1 para abrir apenas o VS Code, sem iniciar o banco. Se a aula usa MariaDB, escolha 2 para abrir o VS Code e iniciar o banco, ou 3 para abrir o terminal do kit com o banco ativo. Use exit para voltar ao menu.

Use a opção 4 para diagnosticar, 5 para exportar o banco e 6 para encerrá-lo.

Se o editor pedir confiança, revise os arquivos e confirme somente para a cópia de materiais que recebeu do professor. A confiança não é desativada pelo kit.

2. Programar

As pastas de projeto estão limpas e prontas para você criar seus arquivos. Abra no VS Code a pasta da linguagem que vai usar. A pasta Java já inclui a configuração do editor para localizar o driver JDBC.

Para acessar a página PHP pelo navegador, execute lab web e abra http://127.0.0.1:8080. Ctrl+C encerra o servidor web. No Linux, o kit usa o PHP incluído no FrankenPHP e fornece o comando php para scripts e Composer.

3. Banco de dados

Endereço 127.0.0.1, porta 3307, banco aulas, usuário aluno. A senha é gerada na primeira execução. No terminal do kit, as variáveis DB_HOST, DB_PORT, DB_NAME, DB_USER e DB_PASSWORD estão disponíveis para os projetos. Cada sistema guarda suas credenciais em estado/<sistema>/credenciais.json.

Os dados do Windows e do Linux são separados. Para levar os dados de um sistema para o outro, exporte com a opção 5 ou lab backup. No outro sistema, importe o arquivo SQL:

lab importar "caminho/para/backup.sql"

A importação pede confirmação e exporta o banco atual antes de aplicar o SQL. Arquivos SQL podem substituir tabelas; use os seus backups ou os fornecidos pelo professor.

4. pip e Composer offline

O pip utiliza apenas a pasta dependencias/python, sem consultar o PyPI. Os pacotes instalados ficam dentro do kit, separados por sistema. Consulte a versão e os pacotes disponíveis com pip --version e pip list.

O kit não depende de uma .venv copiada. Se criar uma venv para um projeto, recrie-a após mudar de pasta ou computador e instale as dependências locais.

Composer está disponível como arquivo PHAR e usa o PHP do kit. O acesso ao Packagist está desativado para evitar downloads durante a aula. O professor precisa preparar cada dependência e as dependências dela em dependencias/composer/pacotes antes de distribuí-la. Para acrescentar pacotes Python, use os wheels de dependencias/python.

5. Git sem internet

No terminal do kit, configure sua identidade. A configuração global usada aqui fica nesta cópia do kit.

git config --global user.name "Seu Nome"
git config --global user.email "seu-email@example.com"
git init meu-projeto
cd meu-projeto

Depois de criar arquivos:

git add .
git commit -m "Primeira versão"
git switch -c atividade
git log --oneline

Para entregar o histórico após fazer commits, use git bundle create entrega.bundle --all. Para receber um projeto, use git clone entrega.bundle projeto. Bundle leva o histórico versionado: inclua as alterações em commits antes de gerar a entrega. Commit, branches e merges locais funcionam sem conta em serviços online.

6. Encerrar e transportar

Feche os servidores web, terminais e o VS Code. No menu escolha 0 para sair; o MariaDB deste kit será encerrado se estiver ativo. Também pode usar a opção 6 ou lab parar. Aguarde a confirmação e só então copie a pasta ou remova a unidade. Não mova o kit com processos ativos.

Projetos ficam em projetos; exportações SQL em backups; banco, configurações e pacotes instalados em estado. Não apague estado para solucionar problemas sem preservar seus dados.

Quando algo não abrir

  • Linux: permissão negada: copie para uma pasta do usuário que permita execução e inicie com sh iniciar-linux.sh. O iniciador restaura as permissões dos executáveis. Uma unidade montada com noexec precisa ser substituída por uma pasta permitida.
  • VS Code e sandbox no Mint: algumas políticas de AppArmor/namespaces bloqueiam aplicativos Electron extraídos. O kit não usa --no-sandbox. Encaminhe o erro ao responsável pelo laboratório para disponibilizar um VS Code permitido; enquanto isso, o terminal e um editor já autorizado podem ser usados.
  • Porta 3307 ocupada: encerre a outra cópia pelo iniciador dela. O kit recusa encerrar um banco que não consegue identificar como seu.
  • Windows: DLL ou aplicativo bloqueado: execute o diagnóstico e informe o erro ao professor. O pacote leva DLLs do runtime junto aos aplicativos, mas políticas institucionais de execução precisam permitir esses programas.
  • Erro do banco: consulte estado/<sistema>/mariadb.log e mariadb-console.log. Preserve os arquivos de dados.
  • Extensão pedindo download: informe qual extensão ao professor. O kit inclui os componentes das extensões selecionadas, mas a ativação deve ser validada com a rede desligada.

As versões, origens e hashes dos downloads estão em componentes.lock.json; o tamanho e o estado de validação constam em PREPARACAO.json. As licenças dos componentes acompanham suas respectivas pastas, incluindo legal do JDK e os arquivos copyright do sysroot Linux.
